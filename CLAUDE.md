# CLAUDE.md

## Что это

**Skedy** (от *schedule*; раньше «המערכת שלי») — веб-приложение (PWA) с личным расписанием ученика параллели י׳ (10-е классы). Ученик один раз выбирает класс и свои группы (математика, английский, мегамот и т. д.) и дальше видит только свои уроки на день, уже с изменениями: отмена, другой кабинет, контрольная, экзамен. Редакторы по коду входят в режим редактирования и публикуют изменения для всех.

- Сайт: GitHub Pages, `https://school-schedule.github.io/`. Деплой автоматический: всё, что попало в ветку по умолчанию, сразу видят ученики.
- Сервер данных: Cloudflare Worker (адрес в `config.js`). Его код — в `worker/` (`src/worker.js`, `wrangler.toml`), скачан из Cloudflare. Работающий Worker обновляет **GitHub Actions** (`.github/workflows/deploy-worker.yml`): когда изменения в `worker/src/` или `wrangler.toml` попадают в `main`, запускается `wrangler deploy` (секреты репозитория `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`; вручную — Actions → Deploy Worker → Run workflow). Значит, слияние PR с Worker = обновление Worker: сливать только после «готово» автора. Можно и вручную: `cd worker && npx wrangler deploy`. Секреты (`EDITOR_CODE`) — только в Cloudflare Secrets, никогда в коде.
- Без сборки, без фреймворков, без npm: чистые HTML + CSS + JS (ES5-стиль: `var`, `function`).
- Три языка интерфейса: иврит (по умолчанию, RTL), английский, русский.

## Цель: полностью заменить שחף в школе (расписание)

Решение автора (11.2026): в будущем школа ведёт **расписание** только в Skedy — уроки, изменения, контрольные, выходные, уведомления. Оценки и посещаемость остаются в שחף (личные данные, связь с Министерством). Когда школа ведёт расписание в Skedy Admin, скачивать с сайта שחף больше не нужно — пропадает и юридический риск (правила сайта שחף). **личная ссылка учителя** `/teacher/#tk=<имя>.<ключ>` (`TK`, `skedyT.tk`; заголовки `X-T-Name`/`X-T-Key`, `tkHead`) — открывает записи его личных встреч и экран `preq` «💬 Просьбы родителей о разговоре» (`renderPreq`, GET `/preq/list` — просьбы классов, где он классный руководитель; Опрос сервера (`load(light)`): при запуске — всё; раз в 5 минут и при возвращении в приложение (не чаще раза в минуту) — только `/data`, `/ttch`, `/tmsg`, и только пока приложение на экране; `/tt` и файлы — не чаще раза в 30 минут (бесплатные лимиты Cloudflare). | `admin/index.html` | **Skedy Admin** — расписание всей школы для тех, кто его составляет (`/admin/`, под компьютер, на телефоне тоже открывается; ссылка — во вкладке «Ещё» Skedy Teachers, `noindex`). Вкладки: «Классы», «Учителя», «Кабинеты» — сетка недели (дни × уроки) выбранного класса, учителя или кабинета, список слева с поиском и числом занятых уроков; «Параллель» — все классы параллели за выбранный день (классы × уроки). Клетка с несколькими группами (мегамот, הקבצות) — по строке на предмет (×N) и число групп; нажатие на клетку — панель со всеми группами: предмет, учитель, кабинет, классы (по нажатию — переход к учителю, кабинету, классу). Данные — сначала GET `API/tt` (расписание, сохранённое в Skedy), если его нет — `teacher/classes/*.json` из שחף (тот же `build.py`); одинаковый урок у нескольких классов — одна запись со списком классов (правка меняет его у всех этих классов). Время уроков и переводы — из `API/data` и `teacher/subjects.json`. **Редактирование** (кнопка «Редактировать», код редактора Skedy, POST `/login`, код в `sessionStorage["skedyA.code"]`): в панели клетки у каждого урока день, урок, предмет, учитель, кабинет (подсказки из всех значений), классы (чипы ×, «+ класс»), «Удалить», «+ урок»; правки сразу идут в черновик `localStorage["skedyA.draft"]` = `{base, n, tt}` (годится, только если `base` совпадает с версией на сервере), «Сохранить» — POST `API/tt` с `X-Editor-Code` и `base` (409 — кто-то сохранил раньше), «Отменить изменения» — сбросить черновик. У урока обязательны предмет и хотя бы один класс. Формат `tt`: `{updatedAt, cls:[{k,he,g,n}], s, r, t, l:[[день, урок, s, r, t, [классы]]], ok:[ключи], q:[нормы часов], th:{учитель: часов ставки}, co:[ограничения], ro:[роли учителей]}` (`co` — см. «Ограничения» ниже и `worker/`). Сохранённое постоянное расписание видно в **Skedy Teachers** (`ttApply` там), в приложении учеников — **нет**; изменения на даты и дни без учёбы видны и **ученикам י׳** (см. `extChanges` в `index.html`). **Проверки** (`issues()`): учитель на одном уроке в разных кабинетах (`tTwice`) и кабинет на одном уроке у разных учителей (`rTwice`; «не кабинеты» `SKIPR`, как в `build.py`, не проверяются) — красной рамки на клетках сетки нет (убрана по просьбе автора; `lsBad` остался), предупреждение в панели клетки (`slotWarn`), вкладка «Проблемы» (`issues`, число на вкладке) со списком и кнопками «Открыть» и (в редактировании) «Это нормально» — ключ проблемы (тип, день, урок, имя и хеш уроков клетки: если уроки поменяются, проблема покажется снова) в `tt.ok`; при сохранении лишние ключи выкидываются (`ttForSave`). **Изменения на даты** (вся школа): изменения видны **всегда**: при открытии `ui.week` = текущая неделя (если `prefs.showCh` не `false`), над сеткой стрелки, «Эта неделя» и «Скрыть изменения» / «Показать изменения» (`weekBar`, выбор запоминается в `prefs.showCh`); постоянное расписание правится (панель `editPanel`, перетаскивание), когда изменения скрыты — подсказка `chPermHint` в панели; в неделе — даты в шапке, у уроков метки «Отменён» (зачёркнут) / «→ кабинет» / «Контрольная» и примечание (`chFor`, `chTag`), в клетке с группами — «Изменений: N»; Пока у редактора неопубликованные правки (`dirty`), `loadRemote` не меняет `STATE`: иначе база публикации стала бы новой и 409 не сработал бы — чужие изменения молча затёрлись бы.
- **render** — `render()` собирает весь HTML строкой и кладёт в `#root.innerHTML`. Обработка кликов — делегирование по атрибуту `data-act="…"` (большой `switch`), плюс свайп для смены дня.
- **start** — выбор стартового экрана, **заставка при запуске** (`.splash`, ~0,7 с: логотип с пружинкой и лаймовой волной, «Skedy», потом растворяется, и карточки въезжают заново — `.wrap.enter`; экран под ней уже готов, ничего не задерживает; нажатие пропускает; при «уменьшить движение» её нет), аналитика Cloudflare (только на `school-schedule.github.io`), регистрация `sw.js`.

## Модель данных (`app-state`)

```
periods  [{n, start, end}]                         время уроков, n = номер урока
subjects [{id, he, en, ru, multi?, open?}]         предметы; с группами = «выбор» (cat_math, cat_eng, cat_b …); open — группы не делятся по классам
groups   [{id, subjectId, he, en, ru, teacher?, classId?, exceptClasses?}]
classes  [{id, he, en, ru, letter, num}]           например י׳2: letter "י", num 2
lessons  [{id, day 0–4 (вс–чт), period, subjectId, aud:{type:"class"|"group", id}, teacher, room}]
changes  [{id, date "YYYY-MM-DD", lessonId, type:"cancel"|"room"|"test"|"exam", room?, note?}]
events   [{date, text, off, cls?, from?, to?, room?, teacher?}]  события из שחף («אירועים»), пишет только Worker; off = учёбы нет; cls — если не для всех классов; from/to — уроки; teacher — событие одной группы (видят ученики этого учителя)
updatedAt, version, gradeName, migrations
```

- Личное расписание = уроки класса ученика + уроки выбранных им групп + изменения на дату.
- Свободные уроки **не хранятся** — это номера уроков без занятия.
- Выбор ученика (`localStorage["sched.prefs"]` = `{lang, classId, groups:{subjectId: groupId | [groupIds] | "__none"}}`) ссылается на **id**. Переименовывать можно, но менять или удалять id нельзя: у учеников сбросится выбор.
- Учебные дни: воскресенье–четверг. Пятница и суббота пропускаются (`schoolDay`, `stepDay`).

## Правила работы

1. **Не читать `index.html` целиком.** Строка 311 весит ~120 КБ. Ищи через Grep, читай куски через `offset/limit`, а данные разбирай скриптом (Python/Node: найти `id="app-state">` и распарсить JSON).
2. **Без сборки и зависимостей.** Не добавлять npm, бандлеры, фреймворки, внешние скрипты. Стиль кода — как вокруг: ES5, `var`, короткие функции, HTML через конкатенацию строк.
3. **Всё, что попадает в HTML, — через `esc()`.**
4. **Любой новый текст интерфейса — сразу на трёх языках** (`T.he`, `T.en`, `T.ru`). Проверять вёрстку и в RTL (иврит), и в LTR.
5. **Только сервер.** Вход и публикация идут только через Cloudflare Worker (`/login`, `/data`). Не возвращать проверку кода в браузере и публикацию без сервера. `config.js` и манифест должны оставаться в `<head>`.
6. **Данные расписания правятся осторожно.** На сайте живые данные берутся с сервера, поэтому правка встроенного `app-state` сама по себе их не меняет. Перед массовой правкой данных уточни у пользователя. Новые id не должны совпадать с существующими. Ссылки (`subjectId`, `aud.id`, `lessonId`) должны указывать на существующие записи.
7. **Палитра p2 перекрывает базовые стили.** Если стиль «не применяется», ищи правило `html[data-look="p2"] …` или `html[data-look^="p"] …` ниже в CSS.
8. **Не трогать без запроса:** адрес API в `config.js`, токен Cloudflare Analytics, хеши кода редактора, логику 409-конфликта при публикации.
9. **Мобильные первым делом:** крупные кнопки (≥44px), `env(safe-area-inset-*)`, тёмная тема.
10. Коммиты маленькие и с понятным описанием. Пуш в ветку по умолчанию = публикация для всех учеников.

## Проверка

Тестов нет. После каждого `Edit`/`Write` автоматически срабатывает хук `.claude/hooks/check-code.mjs`:

- `teacher/index.html` — синтаксис JS в `app-js`, `config.js` и манифест в `<head>`;
- `parents/index.html` — то же, что у `teacher/index.html`;
- `admin/index.html` — синтаксис JS в `app-js`, `config.js` в `<head>`;
- `*.js` — синтаксис (`.mjs` — как модуль, через `node --check`, без запуска); `*.json`, `*.webmanifest` — корректный JSON.

Если хук нашёл ошибку, исправь её до продолжения работы. Ручной запуск: `node .claude/hooks/check-code.mjs index.html`.
